# Рабочая последовательность

1. **Pre-flight:** прочитать `docs/context/`; проверить `pwd`, ветку, HEAD, upstream, `git status` и полный незакоммиченный diff.
2. **Анализ:** изучить целевой код, связанные определения, вызовы, consumers и существующие проверки. Сверить текстовый контекст с кодом и Git.
3. **Минимальный plan:** определить наименьшее изменение, критерии готовности, риски и разрешённые действия.
4. **Точечная реализация:** сохранить пользовательские изменения и менять только необходимые файлы и строки.
5. **Diff check:** просмотреть полный итоговый diff и выполнить `git diff --check`.
6. **Syntax/static tests:** запустить доступные линтеры и статические проверки. Оборванный pipeline не считать выполненной проверкой.
7. **Synthetic tests:** проверить позитивные, негативные и граничные случаи в изоляции, без записи редакционных данных.
8. **Dry-run:** запускать только при явном разрешении и подтверждённом отсутствии создания кандидатов, черновиков и публикаций.
9. **Проверка побочных эффектов:** проверить Git status, временные данные, run logs и отсутствие неожиданных записей или изменённых файлов.
10. **Обновление контекста:** после значимой задачи актуализировать `current-state.md`; при архитектурном решении — также `decisions.md` и `architecture.md`.
11. **Commit:** получить отдельное разрешение или применить
    согласованный автономный цикл; проверить точный scope перед commit.
12. **Push:** получить отдельное разрешение или применить
    согласованный автономный цикл; отправлять только в согласованный
    upstream.
13. **Deploy:** получить отдельное разрешение после push и согласовать target и процедуру.
14. **Post-deploy verification:** проверить версию, доступность, логи и ключевой безопасный сценарий; зафиксировать фактический результат в контексте.

Изменения базы, merge и rebase всегда требуют отдельного явного
разрешения. SSH и scp без отдельной остановки допустимы только для
изолированного PHP lint или diagnostics явно согласованного
технического этапа и только по правилам удалённых проверок ниже;
остальные SSH/scp требуют отдельного разрешения.

## Автономная работа

После получения задачи самостоятельно пройти безопасный цикл:
pre-flight → анализ → минимальные изменения → доступные проверки →
обновление контекста → итоговый отчёт.

После явного согласования технического этапа разрешён полный цикл:
pre-flight → implementation → diagnostics → PHP lint → context update
→ commit → push → final verification.

Commit и push без дополнительной остановки допустимы только если:

- работа идёт в согласованной ветке `admin-editorial`;
- изменены только файлы согласованного этапа;
- working tree до начала этапа был чистым;
- нет чужих или неожиданных изменений;
- все предусмотренные проверки и `git diff --check` прошли;
- секреты не добавлены;
- commit не содержит несвязанных изменений;
- push выполняется только в `origin/admin-editorial`.

Не останавливаться после каждого безопасного шага и не запрашивать
подтверждение на обычное чтение, локальное редактирование workspace,
`git diff` и статические проверки.

Всегда остановиться перед:

- deploy;
- изменением базы данных;
- изменением рабочего WordPress на сервере;
- платным OpenAI API request;
- destructive Git operation;
- изменением продуктового контракта;
- неожиданной ошибкой или несвязанным изменением.

## Удалённые технические проверки

- Использовать только SSH-алиас `revelations-prod`, никогда не сырой IP.
- Не запрашивать и не сохранять пароли.
- Работать только в новой уникальной директории внутри удалённого `/tmp`.
- Передавать только минимально необходимые файлы.
- Не изменять рабочий WordPress, базу данных или серверную конфигурацию.
- Не устанавливать пакеты или расширения без отдельного разрешения.
- После проверки обязательно удалить локальные и удалённые временные файлы.

## Полная AI generation regression suite

Из корня репозитория:

`wordpress-cms/bin/test-editorial-ai-generation-suite.sh`

Runner сохраняет отдельные результаты component, integration и
upstream AI gate diagnostics и возвращает non-zero, если провалился
хотя бы один набор. Для полного запуска требуются PHP с `mbstring` и
Node; при отсутствии локального PHP запускать только в согласованной
уникальной `/tmp`-директории через `revelations-prod`.
